# 月次レポート

店舗ごとの月次レポートを、毎月同じ形で作るための道具です。
Claude Code に「11月のレポート作って」と頼むと、`.claude/skills/monthly-report/SKILL.md` の手順で作ります。

## ファイル

| ファイル | 役割 |
|---|---|
| `fetch_month.py` | 財務アプリのデータ（Supabase）から1か月分の数字を集め、JSONで出す。読むだけで書き込みはしない |
| `make_pdf.js` | レポートのHTMLをA4のPDFにする |
| `stores/<店舗>.json` | 店舗ごとの設定（店名・データの場所・主原料の換算・毎月聞くこと） |

## 準備（最初に1回）

クラウド環境の設定に、次の2つを環境変数として登録します（LINE bot に設定してあるものと同じ値）。
- `SUPABASE_URL`
- `SUPABASE_ANON_KEY`

Squareの出数は、LINE bot が毎日 Supabase に保存しているので、Squareのキーは要りません。

## 計算のきまり（2026年10月分で決めたもの）

- **売上**：現金売上＋法人入金＋個人入金（`line-bot-vercel/linebot/finance.py` と同じ）。税込。
- **税抜**：経費は明細ごとに「税込 ÷（1＋税率）」で出して合計し、1円未満を切り捨てる。売上は「税込 ÷ 1.08」。
- **売上比**：税抜の売上に対する割合。
- **人件費**：財務アプリの人件費の明細。アルバイトの日数・時間は打刻（シフト）から出す。
- **主原料（神田は鰻）**
  - 仕入れは、食材のうち品名か仕入れ先に「鰻」が入る明細。1回100尾。
  - 実際の使用量 ＝ 月初の在庫 ＋ 仕入れ − 月末の在庫（棚卸し）。
  - 月末の在庫の金額は、最後に入荷した回の1尾あたりの単価で計算する。
  - レジの出数からの換算は、鰻重の特上1.5尾・上1尾・並0.5尾。
  - 実際の使用量と出数の換算との差は、インフルエンサーへの提供と焦がしで説明し、残りを「説明できない分」として出す。
- **インフルエンサーへの無料提供**：収支表では鰻の費用の内訳として「うちインフルエンサー提供（広告宣伝）」の行に出す。経費合計と損益は変わらない。原価は鰻の分だけ（その月の実際の1尾あたり単価 × 尾数）。
- **客単価**：売上 ÷ お金を払ったお客様の人数（日報の人数から無料提供の人数を除く）。
- **在庫を除いた損益**：損益に月末の在庫の金額を足し戻したもの。

## 他の店舗を足すとき

1. `stores/kanda.json` をコピーして `stores/<新しい店舗>.json` を作る。
2. 店名、データの場所（`kv_table`・`kv_prefix`）、主原料（品名・換算・1回の仕入れ量）、毎月聞くことを書き換える。
3. 今の財務アプリのデータは1店舗分（`birdmen:`）だけです。2店舗目を財務アプリで管理するときは、
   店舗ごとにデータを分ける（キーの頭を変える・別のテーブルにする等）必要があります。分け方が決まったら、この設定に書きます。
4. 主原料が無い業態なら、`main_ingredient` を外し、レポートの「主原料の使用量と原価」の章を省きます（スクリプトはそのまま動きます）。
