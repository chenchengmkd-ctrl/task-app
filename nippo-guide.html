1. このアプリは何か

鰻のお店（屋台）で、1日の営業の記録＝日報 をつけて、スタッフのLINEグループに送るためのWebアプリです。

項目 内容
使う人 お店のスタッフ（記入者。初期値：江夏・工藤・上原・都丸）
使う端末 主にお店のiPad。スマホからも続きを書ける
公開URL https://chenchengmkd-ctrl.github.io/task-app/nippo.html （GitHub Pages）
ファイル nippo.html 1枚（HTML・CSS・JavaScript がすべて入っている。ビルド不要）
サーバー側 line-bot-vercel/（Vercel上のPython）に日報用のAPIが2本ある

できること

  • 会計ごとに「来店経緯」を記録（インスタ・看板・リピーター…）。人数・食べたもの・性別年代・お客さんの反応も一緒に。
  • 売上はSquare（レジ）から自動取得。手で打たなくていい。会計ごとの注文明細も自動で入る。
  • 常連さん台帳。リピーターを選ぶと来店回数・よく頼むものが自動でたまる。
  • iPadとスマホで同じ日報を編集（サーバー経由で同期）。
  • ボタン1つでLINEグループへ送信（勤怠Bot経由。iPadにLINEアプリが無くても送れる）。

2. 1日の流れ（使い方）

いつ 画面 入れるもの
開店 ① 開始画面 日付・記入者・天気
営業中（会計のたびに繰り返す） ② 会計を記録 人数・食べたもの（Squareから自動）・来店経緯（必須）・性別年代・お客さん・反応（任意）
閉店 ③ 申し送り・実績 申し送り事項・インバウンド・売上と累計（自動）
最後 LINEで送る 送信後、翌日の開始画面に進む

① 開始（1日1回）

  1. アプリを開くと「今日の日報」画面。
  2. 記入者（複数可）と 天気 を選んで「はじめる」。
  3. 以後この画面は出ない。直したいときは上部の「日付・天気・記入者　変更 ›」の帯をタップ。

② 会計を記録（お客さん1組ごと）

  1. 会計が終わると、Squareの会計が横並びのカードで出る（最新のものが自動で選ばれる）。
  2. 人数 を押す（6人以上は「6+」）。テイクアウトなら「テイクアウト」。
  3. 食べたもの はSquareから自動で入る（特上・上・並・おにぎり・混ぜご飯）。手で足すこともできる。
  4. 来店経緯 を押す（ここだけ必須）。
  5. 1組の中で人ごとに違うときは、別のボタンも押す。同じボタンをもう一度押すとその人数が1人増える。 例：3名で「インスタ」→「看板」→「看板」と押すと インスタ1・看板2。
  6. 「リピーター」を押すと常連さんを選ぶ画面が出る（新規登録もここでできる）。
  7. 任意で 性別・年代（人数分まで）、どんなお客さん、反応 を選ぶ／書く。
  8. 一番下の 「この会計を記録する」 で確定。下の「記録済み」に並ぶ。

間違えたら「↶ 元に戻す」。記録済みカードの「編集」から後で直すこともできる。

③ 営業おわり

  1. 「営業おわり → 申し送り・実績へ」を押す。
  2. 申し送り事項・インバウンド（話せた方・口コミ依頼人数）を入力。
  3. 実績 の本日売上・累計売上はSquareから自動。確認だけ。
  4. 下の 「LINEで送る」 → 確認 → 送信。送信後は翌日の開始画面に進む（トーストの「取り消す」で戻れる）。

送る前に「プレビュー」で文章を確認できます。「コピー」で手動貼り付けもできます。

3. 画面ごとの説明

画面は1つのHTMLの中で <div class="page" id="p-○○"> を切り替えて表示しています（go() 関数）。

画面ID 名前 開き方 内容
p-start 開始画面 初回／上部の帯 日付・記入者・天気
p-form 会計の記録 メイン 会計記録パネル＋記録済み一覧
p-end 申し送り・実績 「営業おわり」 申し送り・インバウンド・売上
p-prev プレビュー 下部「プレビュー」 送信される文章そのもの
p-hist 履歴 ヘッダー「履歴」 過去の日報を開く／削除、バックアップ保存（JSON）
p-reg 常連 ヘッダー「常連」 常連さんの一覧・特徴・メモ・来店履歴
p-set 設定 ヘッダー「設定」 合言葉、累計の数え方、営業報告に載せる組

ヘッダーの「新規」は「今日の日報を開く」ボタンです（過去の日報を開いた後に今日へ戻るとき用）。

設定画面の項目

項目 意味
合言葉 サーバーの NIPPO_TOKEN と同じ文字。入れると Square連携・端末間同期・Bot送信が有効になる。未入力だとその端末だけで動く
累計売上 「月ごと」（毎月1日にリセット、既定）／「ずっと足し続ける」
営業報告に載せる組 「記録した組すべて」（既定）／「反応・お客さん情報を入れた組だけ」

4. 全体の仕組み

nippo.html（iPad／スマホのブラウザ。画面と入力、日報は端末の localStorage に保存）
 │
 ├─ ① 売上 ─→ task-app（Vercel） /api/nippo_sales ─→ Square
 │
 ├─ ② 同期 ─→ task-app（Vercel） /api/nippo_sync  ─→ Supabase（bot_state）
 │
 └─ ③ 送信 ─→ 勤怠Bot（Vercel・別リポジトリ） /api/nippo_post ─→ LINEグループに投稿

task-app 側の入口は line-bot-vercel/app.py、勤怠Botは line-kintai-vercel という別プロジェクトです。

通信先 URL（nippo.html 内の定数） 役割
① API https://task-app-nine-liard.vercel.app/api/nippo_sales その日のSquare売上・月累計・会計明細を返す
② SYNC_API https://task-app-nine-liard.vercel.app/api/nippo_sync 日報と共有データを端末間でやりとり
③ SEND_API https://line-kintai-vercel.vercel.app/api/nippo_post 日報文をLINEグループに投稿
  • 3つとも HTTPヘッダー X-App-Token: <合言葉> で認証します。合言葉が違うと 401 合言葉が違います。
  • ③の勤怠Botは このリポジトリには入っていません（line-kintai-vercel という別プロジェクト）。中身を直すときはそちらを見てください。

保存場所

データ 一次保存 共有先
日報（1日1件） 端末の localStorage nippo_all Supabase bot_state テーブル、キー nippo:r:YYYY-MM-DD
常連・名前・よく使う言葉・設定 localStorage の各キー Supabase bot_state、キー nippo:shared
合言葉 localStorage nippo_sqkey 共有しない（端末ごとに入力）
