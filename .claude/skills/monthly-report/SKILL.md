# 月次レポートの作り方

10月分（2026年10月）で決めた形を、毎月同じように作るための手順です。
詳しい計算のきまりと、店舗の足し方は `monthly-report/README.md` にあります。最初に読んでください。

## 1. 店舗と月を決める
- 店舗の指定がなければ `kanda`（神田の屋台うなぎ）。店舗の一覧は `monthly-report/stores/*.json`。
- 月の指定がなければ前月。

## 2. 数字を集める
```
python3 monthly-report/fetch_month.py --store kanda --month YYYY-MM > <scratchpad>/month.json
```
- `SUPABASE_URL` と `SUPABASE_ANON_KEY` が無いと止まる。そのときは、作り話の数字で埋めずに、
  クラウド環境の設定（セッションのタイトル部分の環境メニュー → Edit）に登録してもらうよう伝える。キーをチャットに貼ってもらってはいけない。
- `missing_days` を確認し、入力漏れの日（営業日なのに財務データやSquareの明細が無い日）があれば最初に伝える。

## 3. 毎月聞くこと（データに無いもの）
店舗設定の `monthly_inputs` を、まとめて1回で聞く。神田なら:
1. 月初と月末の鰻の在庫（尾数）
2. インフルエンサーへの無料提供（店内・持ち帰りの食数）
3. 焦がし・廃棄（尾数）
4. その月だけの出来事（臨時休業・イベント・値上げなど）

分からない項目は空欄のまま進め、レポートに「未確認」と書く。推定で埋めた数字には「推定」と書く。

## 4. 日報を読む
- 客数（人数）・来店経緯・お客様の反応・申し送り・在庫・チラシの記録を、その月の分だけ読む。
- 日報の保存先は店舗設定の `nippo_source`。空なら、日報のテキスト（LINEのスタッフグループの書き出しなど）を渡してもらう。

## 5. レポートを書く
- 前の月のアーティファクト（店舗設定の `report_artifact`）を `Artifact` の read で読み、同じ章立て・見た目で作る。
  章の順番: 今月の要点 → 収支表 → 主原料の使用量と原価 → 日別の売上 → 来店経緯 → お客様の声 → 現場の運営 → 来月に向けて → 出典
- 新しい月は新しいアーティファクトにする（前の月を上書きしない）。作ったら店舗設定の `report_artifact` を新しいURLに更新する。
- 数字は month.json と、3で聞いた値だけを使う。計算したら、合計と内訳が合っているかを必ず確かめる。
- 文章はやさしい日本語で、専門用語を避ける。日報の文章は要約し、日付を添える。

## 6. 確認してから確定
- まず下書きとしてリンクを渡し、「直したい数字・言い回し」を聞く。
- 直すときは、関係する数字（合計・税抜・売上比・原価率・損益・要点の文章）をまとめて計算し直す。

## 7. PDFにする
```
node monthly-report/make_pdf.js <レポート.html> <作業フォルダ>/reports/YYYY-MM_<店舗>_月次レポート.pdf
```
- PDFには人件費などが個人名つきで入るので、リポジトリにはコミットしない（`reports/` はコミット対象外）。
